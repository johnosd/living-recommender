Entrega

Sem API no MVP

Os dados são estáticos e o ranking roda no navegador. Isso deixa o custo perto de zero, dispensa operar servidor e mantém as preferências no dispositivo.

Reabrir se: surgir inferência por imóvel, contas de usuário ou dados grandes demais para baixar (bem acima de 5 MB).

Orquestração

MWAA Serverless

Escolha sua. Aceita só operadores do Amazon Provider, por isso o Databricks não entra por operador nativo.

Plano B: Step Functions + EventBridge, se a PoC da Fase 1 falhar.

O volume fica abaixo de 1 GB, e um container curto por mês dá conta.

Reabrir se: os dados processados passarem de ~50 GB ou o job passar de 30 min.

Laboratório · ADR-001 aceita

Databricks fora do caminho crítico

Entregas: EDA, pipeline espelho do Idealista em PySpark/Delta comparado ao dbt, e MLflow para o modelo de aluguel. Recebe só extratos manuais e não guarda nenhuma credencial de produção.

Por que não em produção: a Free Edition proíbe uso comercial, não aceita armazenamento próprio, restringe a saída de internet, não tem operador no MWAA Serverless e não tem SLA.

Dados

Idealista manual e agregado

Coleta mensal pela extensão, com upload e manifest, até a API oficial sair. Nenhum anúncio individual é publicado.

Granularidade: ranking por município e drill-down por freguesia, com o indicador herdado sinalizado.

4. Ciclo mensal, passo a passo

  1. Você roda a extensão e envia o lote do Idealista com a CLI de upload. O lote vai para raw/ com manifest.
  2. O workflow mensal do MWAA invoca as Lambdas coletoras das fontes públicas.
  3. A tarefa ECS executa dbt build (modelos e testes). Se algum teste falhar, nada é publicado.
  4. A tarefa publish gera os JSON e TopoJSON em published/vN.
  5. Só depois disso o current.json passa a apontar para vN. Para fazer rollback, basta apontá-lo de volta para vN-1.
  6. O CloudFront invalida o current.json, e os próximos visitantes já recebem a versão nova.
